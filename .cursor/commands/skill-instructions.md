# Skill instructions

Write or revise skills.

- Include only what the model would get wrong or not know without the skill, such as project conventions, internal tools, or non-obvious steps. If the model already does a task correctly without help, do not write a skill for it or add it to an existing skill.
- Identify the scenarios that actually need a skill, and cover only those.
- Use the smallest scope and length that gives the most benefit. Short skills work better than long ones, because the model loses track of instructions in large contexts.
- For each supporting file, state when and how to use it. Load supporting files on demand, only when the task needs them.
- In task routing, do not point to files for work that is already done or already exists.
